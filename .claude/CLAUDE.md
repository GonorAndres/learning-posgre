# Project: learning_posgre

Flight analytics platform built around a PostgreSQL 16 demo database (5.74M rows). Spans SQL analysis, BigQuery migration, an ETL pipeline, and a Next.js dashboard deployed to Firebase Hosting.

## Project Structure

| Directory | Purpose |
|-----------|---------|
| `analysis/` | 6 SQL analysis scripts (delays, revenue, utilization, optimization, materialized views, geospatial) |
| `internals/` | 6 PG internals deep-dives (EXPLAIN, indexes, partitioning, statistics, vacuum, WAL) |
| `bigquery/` | 4 translated BQ queries + schema/comparison docs |
| `pipeline/` | Python ETL: `extract.py`, `transform.py`, `load.py`, `run_pipeline.py` |
| `dashboard/` | Next.js 16 + React 19 static dashboard (see Dashboard section) |
| `config/` | `postgresql.conf` (production-like, modeled after Cloud SQL) |
| `init-scripts/` | Docker entrypoint SQL scripts (ordered by filename prefix) |
| `results/` | Pre-computed query output text files |
| `notebooks/` | Jupyter notebook + builder script |

## Docker PostgreSQL
- Run: `docker compose up -d` (container: `learning_pg`)
- Connect: `docker exec -it learning_pg psql -U app_user -d learning_db`
- Config: `config/postgresql.conf`
- Init scripts in `init-scripts/` run once on first volume creation

## Dashboard
- **Framework**: Next.js 16.2.1, React 19.2.4, TypeScript, Tailwind CSS 4
- **Build mode**: Static export (`output: "export"` in `next.config.ts`)
- **Visualization**: Recharts (charts), deck.gl + MapLibre (geospatial maps)
- **Style**: Brutalist aesthetic, i18n (EN/ES)
- **Analytics**: PostHog + Google Analytics (GA4) integrated in `layout.tsx`
- **Pages**: `/` (home), `/overview`, `/delays`, `/revenue`, `/fleet`, `/map`, `/pipeline`, `/internals`
- **Data**: 10 pre-computed JSON files in `dashboard/data/` generated by `dashboard/scripts/prepare-data.py`
- **IMPORTANT**: Read `dashboard/AGENTS.md` before modifying -- this Next.js version has breaking changes vs training data. Check `node_modules/next/dist/docs/` for guides.

### Data refresh flow
```
PostgreSQL -> prepare-data.py -> dashboard/data/*.json -> npx next build -> dashboard/out/
```

### Adding WIF to a new repo (same GCP project)
The WIF pool/provider already exist. Only need:
1. `gcloud iam service-accounts add-iam-policy-binding` with the new repo's principal
2. `gh secret set FIREBASE_SERVICE_ACCOUNT` on the new repo
3. Copy/adapt the workflow YAML

## Firestore (future integration notes)
When adding Firestore to this project:
- The Firebase project (`project-ad7a5be2-a1c7-4510-82d`) already exists with Hosting enabled
- To enable Firestore: `firebase init firestore` (creates `firestore.rules`, `firestore.indexes.json`)
- The `firebase-hosting-deploy` SA will need an additional role: `roles/datastore.user` (for read/write) or `roles/datastore.viewer` (read-only)
- Grant via: `gcloud projects add-iam-policy-binding project-ad7a5be2-a1c7-4510-82d --member="serviceAccount:firebase-hosting-deploy@project-ad7a5be2-a1c7-4510-82d.iam.gserviceaccount.com" --role="roles/datastore.user"`
- If the dashboard needs to read Firestore client-side, add Firebase JS SDK (`firebase` package) and configure with the project's web app config from Firebase Console
- If using Firestore for server-side data (e.g., replacing JSON files), the dashboard would need to switch from static export to SSR (`output: "standalone"`) or use client-side fetching
